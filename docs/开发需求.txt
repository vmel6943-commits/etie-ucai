# 《鹅铁U彩》周一互动网页游戏完整开发需求

## 一、项目定位与总体要求

### 1.1 项目背景

本项目是腾讯鹅创营七日社群互动活动的周一主题网页游戏。

项目名称暂定为《鹅铁U彩》（Goose Express），玩家将以受邀旅客的身份登上一辆充满秘密的奇幻列车，在七天内经历不同的故事、人物互动与主题活动。

本次需要完成周一的完整游戏内容。

周一的登场人物包括：

- 神秘情报贩子：神秘情报贩子。
- 乘务员：乘务员。
- 列车长：列车长，在开场和广播中承担世界观引导。
- 旅行手账相关角色：手账记录员，可用于手账系统的引导，避免抢占周一主要角色的剧情。

所有角色均已有正式鹅设图片，必须以提供的原始素材为准，不得自行重新设计人物造型。

### 1.2 核心目标

制作一款真正可玩的、具有精致美术和沉浸式体验的互动网页游戏。

游戏需要具备：

1. 完整的剧情与人物对话。
2. 可以自由探索的场景和实际可点击的物品。
3. 多种不同操作方式的小游戏。
4. 具有反馈的选择分支。
5. 跨章节延续的道具、车票和任务状态。
6. 隐藏剧情、收集品和可重复探索内容。
7. 能够生成并保存的个性化分享图片。
8. 完整的移动端和桌面端适配。
9. 随时保存进度、返回场景和继续游戏的能力。
10. 方便后续更换舆论事件、NPC台词和周二至周日内容的数据结构。

**最高优先级：完成实际可玩的游戏。**

不能把项目实现成单纯展示美术图片、点击下一页的H5，也不能让多个场景仅通过切换静态图片来模拟游戏。

每个核心交互必须有完整的触发、操作、反馈、成功状态和后续影响。

### 1.3 三幕结构

整个周一游戏分为三个连续章节。

| 章节  | 名称      | 游戏形式    | 核心目标                 |
| --- | ------- | ------- | -------------------- |
| 第一幕 | 午夜发车前   | 沉浸式文字冒险 | 探索车站、领取车票、检票登车       |
| 第二幕 | 皮箱里的十五秒 | 交互式情报调查 | 阅读专报、调查舆论事件、重新判断     |
| 第三幕 | 夜行列车奇遇记 | 开放式场景探索 | 自由探索、制作美食、记录见闻、预告下一站 |

体验递进为：

**文字冒险 → 情报调查 → 自由探索。**

三个章节应当有明显不同的玩法，但视觉风格、角色、背包、任务记录和剧情状态必须统一。

建议主线体验时间：

- 第一幕：6—8分钟。
- 第二幕：8—12分钟。
- 第三幕：8—12分钟。

允许玩家通过跳过已读对话、使用提示和减少非必要探索缩短通关时间。

不得设置强制等待、付费、广告、体力或失败惩罚。

# 二、技术方案与开发方式

## 2.1 开发原则

首先检查当前代码仓库及所提供的素材文件。

如果仓库已有框架、路由、状态管理和构建配置，优先在现有项目基础上开发，不要不必要地重建。

如果没有现成代码框架，建议采用：

- React + TypeScript + Vite。
- React Router，用于章节、场景及必要的页面导航。
- Zustand，用于管理游戏状态。
- localStorage，用于保存第一版游戏进度。
- CSS Modules、Tailwind CSS或其他适合项目的样式方案。
- CSS动画与Web Animations API，用于简单交互和场景过渡。
- 必要时使用Canvas或SVG实现小游戏。
- 通过Canvas或合适的前端图片导出方案生成分享卡片。

优先使用稳定、轻量的实现方式。

不需要为了交互视觉效果引入完整3D引擎。整体采用2.5D场景、分层图片、局部动效和可点击物品的方式实现。

## 2.2 必须坚持的开发要求

**功能优先于展示效果。**

优先完成从开场到第三幕结局的完整闭环，再逐步打磨美术与动画。

**真实操作优先于模拟操作。**

例如，视频还原必须可以实际切换片段，时间线必须可以调整顺序，广播旋钮必须可以实际改变信号状态。

**交互数据与页面分离。**

所有剧情、对话、证据、调查选项、食谱、道具和任务条件都应配置化。

**双端分别设计交互。**

手机端与桌面端可以共享逻辑，但不能完全依赖同一个固定坐标布局。

**保留扩展能力。**

第一版使用浏览器本地存储，不强制开发用户系统和多人服务器。后续接入后端时，游戏状态结构应能复用。

## 2.3 项目资源

本项目已有以下素材包：

1. 原始鹅设素材：`值周7组-烧鹅濑粉-鹅设.zip`
2. 第一幕素材：`鹅铁U彩_第一幕_第一二批双端美术素材_最终版.zip`
3. 第二幕素材：`鹅铁U彩_第二幕_全部素材_含拆分PNG与SVG.zip`
4. 第三幕素材：`鹅铁U彩_第三幕_主场景与补充拆分素材.zip`

部分压缩包可能还包含重复场景或早期效果图。

请先检查实际存在的文件，并建立统一资源索引。

应当区分：

- 原始正式角色图。
- 完整场景背景图。
- 独立透明底PNG。
- 可编辑SVG。
- 手机端布局模板。
- 桌面端布局模板。
- 仅供参考的效果图。

优先使用与游戏场景匹配的正式美术素材，不要重新生成大量通用背景。

发现素材不完整时，可以用CSS、SVG和可复用的前端组件补足。不要因为缺少某个装饰素材就使整个功能失效。

# 三、全局游戏系统

## 3.1 统一导航

网页保留四个主要入口：

**登车大厅、旅途地图、神秘乘客、旅行手账。**

四个入口随着游戏进度逐步开放。

首次游玩时，玩家直接进入第一幕开场，不展示四个全部开放的传统首页。

完成登车后，逐步开放路线地图、人物档案和手账。

第三幕解锁后，玩家还可以通过车厢地图访问自由探索区域。

在任何章节中都应提供：

- 当前任务提示。
- 背包。
- 手账。
- 设置。
- 返回当前场景。
- 已解锁章节或场景导航。

这些功能不能长时间遮挡主画面。

## 3.2 全局状态

至少管理以下数据：

| 状态   | 内容             |
| ---- | -------------- |
| 玩家资料 | 昵称、个人标识、本地记录   |
| 当前进度 | 当前章节、场景、剧情节点   |
| 对话记录 | 已选择选项、已触发分支    |
| 车票   | 车次、座位、外观、检票状态  |
| 背包   | 已获得的道具         |
| 线索   | 已发现、已查看、已确认的线索 |
| 投票   | 初次判断、再次判断、把握程度 |
| 调查记录 | 证据查看和关联完成情况    |
| 探索记录 | 已访问车厢、操作过的物品   |
| 食谱记录 | 美食、配料、纪念印记     |
| 手账   | 各章节产生的纪念与记录    |
| 成就   | 已解锁成就和隐藏奖励     |
| 设置   | 音量、字幕、动画、文字速度  |

游戏进度必须自动保存。

至少在下列时刻立即保存：

- 完成重要对话。
- 获得道具。
- 提交投票。
- 完成小游戏。
- 领取车票。
- 完成检票。
- 制作美食。
- 完成每日手账。

刷新网页后，能够回到合理的剧情位置，不应从第一幕重新开始。

建议支持开始新旅程、继续旅程和重温已完成章节。

重温剧情默认不删除正式进度。

## 3.3 统一对话系统

采用视觉小说式人物对话框。

包含：

- 角色姓名。
- 角色立绘。
- 对话文字。
- 角色表情或姿态变化。
- 选项按钮。
- 已读对话跳过。
- 对话历史。
- 自动播放选项。
- 继续按钮。

文字采用逐字显示，但玩家点击时可以立即展示整段。

不同选择应至少产生不同回应。

关键选择需要记录并影响后续场景中的人物台词。

不要求每个选择都导致独立结局，但不能所有选项都没有反馈。

## 3.4 道具交互系统

道具需要支持不同的操作模式：

- 点击检查。
- 放大查看。
- 正反面翻转。
- 拖动使用。
- 点击选择后应用到目标。
- 多物品组合。
- 收集进入背包。
- 使用后改变场景状态。

移动端不得只支持拖拽。对于所有必须完成的谜题，都应提供点击式替代操作。

## 3.5 提示与防卡关

所有必要谜题都需要渐进式提示。

第一层提示：说明目标方向。

第二层提示：指出相关物品。

第三层提示：明确操作步骤或高亮正确区域。

不要设置导致永久失败的选择。

重要谜题可以设置“自动完成”或“跳过解谜”，但正常玩家应有机会完整体验操作。

## 3.6 成就与收藏

成就奖励以收藏价值和剧情反馈为主。

不设置与主线通关绑定的隐藏收集完成率。

玩家能够在旅行手账中查看：

- 已获得成就。
- 已发现隐藏物品。
- 已完成章节。
- 当前未完成的收藏目标。

隐藏内容要有实际反馈，可以是新台词、特殊印章、纪念卡或附加剧情。

# 四、第一幕《午夜发车前》

## 4.1 故事设定

玩家收到鹅铁U彩事务局寄来的神秘邀请函。

邀请函邀请玩家参加一场七日旅程，但没有提供完整的目的地和车票。

玩家来到夜色中的鹅铁U彩站，探索候车大厅，与乘务员交谈，激活售票机，定制车票并完成检票。

登上列车后，玩家解锁七日旅程路线图与旅行手账，并在车厢尽头遇见携带巨大皮箱的神秘情报贩子神秘情报贩子。

第一幕以情报贩子邀请玩家查看第一份《列车专报》结束。

## 4.2 场景S01：神秘邀请函

**画面：** 复古书桌，中央摆放带火漆印章的信封，周围有怀表、报纸、茶杯和窗外夜景。

**交互：**

玩家点击信封，信封抬起。

点击火漆，火漆开裂。

再次点击或滑动信封盖，展开信纸。

信件正文：

“亲爱的旅客：

当你看到这封信时，鹅铁U彩即将启程。

我们将用七天的时间，经过七段不同的旅程。在这里，你可能遇见有趣的人、听见离奇的消息，也可能重新认识一些原本熟悉的事。

每个人都能带走一份属于自己的旅行记录。

但在此之前，你需要找到前往列车的入口。

请在最后一声汽笛响起前登车。

——鹅铁U彩事务局”

**选择：**

A. 仔细检查信封。

B. 立即出发。

C. 怀疑这是不是恶作剧。

分别产生不同旁白，并记录选择。

**隐藏交互：**

- 检查怀表，发现23:47。
- 翻转信封，发现G-07编号。
- 检查报纸，发现与第二幕有关的残缺标题。
- 翻转信封获得隐藏收藏品“旧式邀请印章”。

完成后切换至车站外景。

## 4.3 场景S02：雾中车站

**画面：** 深蓝色夜晚、复古站房、灯光、薄雾、远处列车与时钟。

使用多层背景实现轻微环境动态。

玩家可以检查：

- 站牌。
- 时钟。
- 远处列车。
- 车站大门。

广播介绍七日列车即将启程，并提醒没有车票的旅客前往大厅。

点击远处列车时，出现携带巨大皮箱的人影。

点击站牌发现G-07，与邀请函编号呼应。

玩家点击大门进入大厅。

## 4.4 场景S03：候车大厅自由探索

这是第一幕的重要探索场景。

需要一张完整的2.5D大厅地图，包括：

- 旧式时钟。
- 七日路线图。
- 服务柜台和铃铛。
- 售票窗口。
- 长椅。
- 无人认领的行李。
- 站台入口。

各个物品均拥有独立点击区域。

**时钟：** 查看时间和车站编号。

**路线图：** 显示七日线路的部分轮廓，其他站点暂未开放。

**服务铃：** 呼叫乘务员，连续点击触发特殊台词。

**旧长椅：** 检查小册子，获得旅行手账残页。

**无人行李：** 检查行李牌，提前发现神秘乘客线索。

**售票窗口：** 需要完成乘务员引导或使用邀请函后激活。

**站台入口：** 未领取车票时无法通过，乘务员会给出提示。

场景随游戏状态发生变化。

例如，乘务员出现后柜台亮灯，领取车票后售票机改变显示，检票成功后站台入口开放。

## 4.5 场景S04：乘务鹅登场

使用原始乘务员乘务鹅形象。

角色戴圆眼镜、穿蓝色制服、佩戴领结。

角色通过轻微弹跳与挥手动作登场。

初始对话：

“欢迎来到鹅铁U彩站！我是今天负责检票的乘务员。”

“让我看看……嗯，行李没有超重，精神状态看起来也不错。请问你的车票在哪里？”

玩家发现自己只有邀请函。

乘务员解释需要先领取正式车票。

提供三个对话选项：

- 为什么邀请函没有说要买票？
- 我的目的地在哪里？
- 这里到底是什么地方？

乘务员分别回答，并最终引导玩家前往售票机。

后续可以再次询问：

- 七日旅程。
- 其他乘客。
- 旅行手账。
- 售票窗口。
- 如何检票。

连续敲击铃铛三次触发隐藏对话与成就。

## 4.6 场景S05：激活售票机

场景切换到老式黄铜机械出票机特写。

玩家需要将邀请函插入插槽。

机器显示：

“请输入列车编号。”

提供三个候选编号：

- G-07。
- D-12。
- K-21。

正确答案为G-07。

如果玩家此前已获得编号线索，则突出显示该线索。

错误时给予提示，不设置惩罚。

确认成功后，机械灯光点亮，齿轮旋转，进入车票制作界面。

隐藏交互：检查“请勿向机器投喂饼干”的提示并再次操作机械手柄，可以打印特殊票据。

## 4.7 场景S06：领取专属车票

这是第一幕的重要社交成果。

玩家需要完成三个步骤。

### 第一步：填写昵称

支持昵称，不要求真实姓名。

设定合理长度限制，超出时明确提示。

### 第二步：选择座位

提供三个车厢：

- A车厢：观景车厢。
- B车厢：故事车厢。
- C车厢：奇遇车厢。

进入车厢后展示座位平面图。

玩家可以选择靠窗、过道或惊喜座位。

第一版不需要实现全体用户实时占座，座位属于玩家个人记录。

### 第三步：选择车票样式

三种车票：

- 午夜蓝。
- 复古羊皮纸。
- 余晖红棕。

票面显示：

玩家昵称、G-07车次、车厢、座位、七日旅程名称、专属编号及检票状态。

车票背面保留七个纪念印章槽位。

### 出票动画

玩家确认后：

齿轮启动 → 打印纸张 → 机械手柄落下 → 车票缓缓出现 → 玩家点击领取。

车票进入背包，状态为“待检票”。

要求支持保存为图片。

## 4.8 场景S07：正式检票

玩家将车票拖入检票机插槽。

手机端支持点击车票后再点击插槽。

正确操作时：

- 检票灯亮起。
- 机械打孔。
- 出现车票印章。
- 闸门打开。
- 乘务鹅祝贺玩家。

如果拥有第一幕隐藏印章，则票面出现额外纪念标记。

检票完成状态必须保存。

## 4.9 场景S08：登上列车

玩家进入站台。

可以：

- 直接登车。
- 回头观察候车大厅。
- 查看其他乘客。
- 检查列车外观。

远处出现神秘情报贩子的剪影。

点击车门后，镜头向前移动，脚步声从站台切换为车厢木地板声。

列车关闭车门，正式启程。

## 4.10 场景S09：七日路线图与手账解锁

进入列车后，玩家点击车厢内的路线图。

显示完整七站结构。

第一站高亮，其余站点锁定。

各站的名称、人物、主题和预告内容均通过配置文件管理。

初始只开放周一。

玩家随后获得旅行手账。

手账记录：

- 车票。
- 座位。
- 检票印章。
- 第一幕获得的物品。
- 相关隐藏线索。

## 4.11 场景S10：第一幕尾声

列车行驶过程中，玩家听到一只沉重皮箱碰撞地板的声音。

转头后，发现神秘情报贩子神秘情报贩子。

她戴着礼帽、穿风衣，身旁是一只巨大的皮箱。

玩家可以主动询问，也可以在远处观察。

角色最终说道：

“第一份情报，似乎已经准备好了。”

“那么，要不要看看这只皮箱里，究竟藏着什么？”

完成第一幕，进入第二幕。

# 五、第二幕《皮箱里的十五秒》

## 5.1 核心玩法

第二幕围绕三个阶段展开：

**阅读专报与初次投票 → 调查更多信息 → 重新判断与讨论。**

玩家可以自主决定部分档案的调查顺序。

本幕采用暂定的虚构舆论事件：

《明明写着24小时开放，图书馆为什么突然关灯？》

该事件只用于测试游戏机制，后续必须能够通过修改数据替换。

所有虚构案例内容需要保留明确的演示标识。

## 5.2 演示事件基本设定

一段15秒的短视频显示，某图书馆工作人员提醒学生离开，阅览室灯光随后调暗。

视频发布者质疑：图书馆宣传24小时开放，为何仍要求离开？

随着调查推进，玩家发现：

- 主阅览室与通宵自习区开放时间不同。
- 初始传播片段省略了部分前后信息。
- 现场沟通的具体情况仍存在争议。
- 新闻标题在二次传播过程中发生了措辞变化。

不要把所有调查结果引导为某一方绝对正确。

事实、人物说法和无法确认的内容需要分别呈现。

## 5.3 场景S11：情报贩子的邀请

神秘情报贩子邀请玩家坐下。

桌面摆放报纸、放大镜、信件、录音机和锁住的皮箱。

角色说明自己喜欢收集同一事件的不同材料。

玩家通过对话选择是否立即查看报道、询问情报贩子背景等。

最终点击桌上的《列车专报》，进入调查。

第一幕发现过行李牌的玩家触发专属回应。

## 5.4 场景S12：阅读列车专报

报纸以可展开、可翻页的形式呈现。

玩家可以检查：

- 新闻标题。
- 图片。
- 发布时间。
- 发布者信息。
- 15秒视频。
- 初始评论区。

视频采用可以实际播放和暂停的分镜播放器。

第一版可以用多帧静态图片、字幕、镜头推拉和音效实现，确保玩家能够完成播放和操作，不必依赖真实视频生成。

初始15秒展示：

工作人员提醒离开、灯光调暗、拍摄者质疑24小时开放。

玩家初次阅读时只能接触初始传播信息。

完成基本阅读后解锁首次投票。

## 5.5 场景S13：第一次观点投票

核心问题固定为：

“基于目前掌握的信息，你更接近以下哪种判断？”

三个选项：

A. 馆方的现场处理方式可能存在问题。

B. 馆方可能是在正常执行管理规定。

C. 目前信息不足，我想先了解更多。

额外记录1—5级把握程度。

玩家确认后，盖下“初次判断”印章。

首次判断需要永久记录在该次调查进度中，不能被后续投票覆盖。

三个选项都能正常推进，不存在错误立场。

## 5.6 场景S14：打开神秘皮箱

皮箱有三个机关位置。

桌面提供三张消息卡片：

- 最早传播的视频。
- 二次转发报道。
- 图书馆后续回应。

玩家需要按照发布时间排序，完成锁扣解谜。

支持拖拽与点击放置。

错误时给予逐级提示。

完成后，三个锁扣依次弹开，箱盖打开，露出完整情报工作台。

## 5.7 场景S15：情报工作台

这是第二幕的主要调查枢纽。

皮箱内部有多个独立文件区域：

- 视频档案。
- 开放时间公告。
- 事件时间线。
- 现场证词。
- 消息传播记录。
- 调查笔记。
- 隐藏物品。

玩家可以自由选择调查顺序。

三项关键证据为：

视频、公告、时间线。

完成这些证据的基本调查后，解锁证据关联板。

其余档案可以继续探索，但不阻止通关。

## 5.8 场景S16：三项关键调查

### 游戏A：视频片段还原

播放器初始仅展示15秒。

时间轴左右存在未查看区域。

玩家通过操作播放器，获取其他时间段的记录。

例如：

- 21:56：工作人员提醒学生整理物品。
- 21:58：发生最初传播的15秒事件。
- 22:03：工作人员指引其他学习区域。

这些片段可以作为不同记录材料呈现，明确来源与时间，不必伪装成同一段连续录像。

玩家发现视频省略了上下文。

完成后获得“视频上下文”线索。

### 游戏B：公告对比

提供两张图：

- 只显示“24小时开放”的裁切截图。
- 显示不同区域开放时间的完整公告。

玩家拖动对比滑块，查看两张图片的差异。

正式交互需要实现连续遮罩效果。

玩家发现：

- 一楼自习区全天开放。
- 主阅览室开放至22:00。

完成后获得“区域开放规定”线索。

### 游戏C：事件时间线重建

提供五张可操作记录卡。

事件包括：

1. 图书馆播放闭馆广播。
2. 工作人员提醒学生。
3. 视频拍摄开始。
4. 主阅览室进入闭馆流程。
5. 工作人员指引其他区域。

玩家根据证据给出的时间信息排列先后。

可以多次调整顺序。

确认正确后，时间轴点亮并生成事件记录。

完成后获得“完整事件时间线”线索。

## 5.9 场景S17：可选深度调查

### 支线A：证词对比

玩家查看两份不同来源的现场证词。

一份来自读者，一份来自工作人员。

通过点击高亮词语、对照时间和关联陈述，找到一致和存在分歧的地方。

不要使用简单的真假评分来判断人物证词。

### 支线B：传播路径追踪

查看原始视频、二次转发、再次传播三个版本的标题。

玩家点击标题中发生变化的措辞。

将变化信息进行关联。

例如，“发生争论”被进一步描述为“关灯赶学生”，再被描述为“无故驱赶”。

完成后获得“追溯源头”纪念印章。

### 支线C：隐藏录音

玩家发现旧磁带并放入播放器。

调整旋钮后，播放一段关于追溯消息来源的隐藏广播。

获得收藏品“旧式录音磁带”。

## 5.10 场景S18：证据关联板

皮箱隔板展开，形成完整的调查线索板。

玩家需要将问题卡片和支持材料关联。

主要问题：

- 图书馆是否承诺整馆24小时开放？
- 15秒视频是否包含完整交流？
- 现场处理方式是否已经能够被充分确认？

前两项可以依据已设置的演示证据获得事实反馈。

第三项涉及仍待核实的情境，允许玩家形成不同判断。

完成后生成三类记录：

**已核实信息、不同说法、尚待核实。**

这些类别需要有真实的数据映射与内容展示，不能仅作为背景装饰。

## 5.11 场景S19：第二次投票

再次显示与第一次完全相同的问题和选项：

“基于目前掌握的信息，你更接近以下哪种判断？”

玩家再次选择A、B或C。

同时记录：

- 当前把握程度。
- 影响自己判断的证据，可多选。

确认后展示两次投票结果。

根据结果产生不同反馈：

- 判断改变。
- 判断保持一致。
- 仍然无法形成明确判断。

还应识别把握程度是否变化。

所有结果都正常通关，不根据立场评判玩家。

生成“观点变化卡”。

卡片显示：

- 玩家昵称，可选择隐藏。
- 初次判断。
- 调查后判断。
- 两次把握程度。
- 影响判断的主要证据。
- 鹅铁U彩标识。

卡片支持保存为图片。

## 5.12 场景S20：第二幕尾声

情报贩子合上皮箱。

乘务鹅来到车厢，邀请玩家继续探索列车。

皮箱里滑落一张纸条：

“下一站的线索，藏在列车最热闹的地方。”

完成后：

- 获得第一份调查记录。
- 获得情报调查印章。
- 解锁观点变化卡。
- 把调查结果写入手账。
- 开放第三幕车厢探索。

完成第二幕后仍能返回查看情报档案。

# 六、第三幕《夜行列车奇遇记》

## 6.1 核心目标

第三幕采用真正的自由探索玩法。

玩家能够在多个车厢区域之间往返。

主要任务包括：

1. 记录首日见闻。
2. 与乘务员互动。
3. 制作带有观点印记的列车美食。
4. 探索环境和隐藏物品。
5. 修复广播并发现下一站预告。
6. 完成第一日旅行手账。

玩家可以选择探索顺序。

不强制按照场景编号依次完成。

## 6.2 车厢地图

设置五个主要区域：

| 区域    | 功能             |
| ----- | -------------- |
| 乘客车厢  | 座位、NPC、行李和留言探索 |
| 观景走廊  | 景物观察、望远镜、隐藏机关  |
| 列车餐车  | 首日见闻、制作美食      |
| 广播角   | 修复广播、获取下一站线索   |
| 旅行手账台 | 整理物品、盖章、完成记录   |

地图采用横向列车剖面或连续车厢结构。

桌面端可以展示更大的空间。

手机端采用局部视野和左右滑动，点击车门移动。

所有已开放区域允许自由往返。

## 6.3 场景S21：自由探索开启

第二幕结束后，乘务鹅邀请玩家看看其他车厢。

神秘情报贩子提示：

下一站的消息已经传上列车，但广播似乎出了问题。

玩家可以选择先去餐车、探索车厢或寻找广播室。

完成后解锁自由探索地图。

## 6.4 场景S22：乘客车厢

玩家可以点击：

- 自己的座位。
- 阅读灯。
- 车窗。
- 行李架。
- 小桌板。
- 公告栏。
- 车厢连接门。

自己的座位读取第一幕保存的选择。

玩家可以坐下、查看欢迎卡、切换阅读灯状态。

检查行李架可以发现广播识别牌。

桌面上提供乘客留言和首日见闻。

部分留言可以触发隐藏支线。

## 6.5 场景S23：观景走廊

场景包含：

- 大型观景窗。
- 望远镜。
- 旧照片。
- 隐藏小柜子。
- 远处夜景。
- 星光和列车行驶环境。

### 望远镜

玩家点击进入圆形观察视角。

可以移动观察方向。

设置三个主要观察目标：

- 山顶建筑。
- 河流石桥。
- 神秘站牌。

发现站牌获得下一站的可选线索。

### 旧照片

照片能够放大、翻转和检查背面。

部分照片记录列车历史。

其中一张带有广播机关的符号。

### 小柜子

柜门有三个可旋转图案。

玩家根据墙面照片线索调整顺序。

成功后获得旅行纪念章。

### 动态彩蛋

列车经过隧道时，窗外光线短暂变化。

玩家继续观察可以获得夜间风景明信片。

## 6.6 场景S24：首日见闻记录

乘务鹅推着餐食小车出现。

使用原始乘务员鹅设，增加推车和记录动作。

乘务鹅询问玩家：

“今天最想记住的是什么？”

提供四项选择：

- 与其他旅客讨论不同看法。
- 找到新线索的过程。
- 奇妙的列车旅程。
- 仍然值得继续讨论的问题。

支持玩家额外输入一小段文字，但不强制填写。

选择和文本写入旅行手账。

若玩家完成第二幕，可以触发与调查结果有关的不同回应。

完成后解锁专属美食制作。

## 6.7 场景S25：列车美食制作

这是第三幕最重要的可玩环节之一。

提供四款基础美食：

| 美食      | 互动方式        | 主题        |
| ------- | ----------- | --------- |
| 反转千层酥   | 逐层叠放酥皮与馅料   | 故事可能还有另一层 |
| 等等再说热可可 | 加入配料、搅拌     | 暂缓判断      |
| 多视角拼盘   | 自由摆放不同点心    | 容纳不同看法    |
| 回声气泡饮   | 选择饮品颜色、加入配料 | 传播中的变化    |

### 具体要求

玩家先选择食物类型。

进入独立制作台。

依次完成：

选择基础 → 添加配料 → 操作制作 → 添加装饰 → 生成成品。

配料必须能实际选择和组合。

美食成品的画面应能根据所选配料产生可见变化。

不要求模拟复杂物理系统，可以通过分层PNG、SVG或其他可复用图层实现。

### 纪念印记

玩家可以选择四种印章：

- 放大镜：多看看细节。
- 问号：保留疑问。
- 对话框：欢迎不同看法。
- 星星：记录旅途惊喜。

印记不自动由玩家的舆论立场决定，而是主动选择。

### 分享卡

制作结束后生成个性化美食卡。

包含：

- 成品图。
- 自定义食物名称。
- 玩家昵称。
- 配料与装饰。
- 纪念印记。
- 周一列车纪念标识。

支持保存为图片。

### 隐藏食谱

设置三款隐藏奖励：

- 月光限定甜点。
- 情报贩子特调。
- 乘务鹅私藏款。

分别通过观景探索、第二幕隐藏调查和餐车秘密菜谱解锁。

隐藏食谱不影响主线完成。

## 6.8 场景S26：车厢秘密

设置三个可选隐藏任务。

### 无名旅客车票

在座位下发现一张旧车票。

车票上没有乘客姓名。

带给乘务鹅检查，获得特殊角色台词和收藏物。

### 旧留声机

在其他车厢寻找唱针。

将唱针安装到留声机。

播放一段关于鹅铁U彩历史的录音。

获得隐藏唱片。

### 秘密菜单

检查餐车抽屉，发现乘务鹅藏起来的菜谱。

解锁隐藏食物装饰或食谱。

以上支线不提前揭晓周二正式角色和活动。

## 6.9 场景S27：广播调频解谜

广播角需要有独立的广播设备特写页面。

玩家进入后，听到断断续续的广播和电流声。

小游戏分三步。

### 第一步：确认频道

提供三个编号：

- G-07。
- K-21。
- D-12。

正确频道为G-07。

线索可以来自第一幕车票、车厢广播牌或现场手册。

### 第二步：调整频率

玩家操作黄铜旋钮。

旋钮转动时，指针真实移动。

信号强度随操作变化。

当指针进入目标区域时，指示灯点亮。

移动端支持滑动或点击加减按钮。

### 第三步：恢复广播

玩家依次查看三个广播片段。

通过声音、字幕和信息提示，恢复下一站预告的正确顺序。

暂定播报内容：

“下一站，我们将迎来一位特别的旅客……”

“这位旅客似乎带来了一件值得大家讨论的事情……”

“更多消息，将在下一站揭晓。”

所有具体周二内容通过配置文件替换。

完成后获得“下一站广播”线索。

可以重复播放，不需要再次解谜。

## 6.10 场景S28：情报贩子隐藏对话

完成广播后，玩家可以回到神秘情报贩子的座位。

此时她正在整理皮箱。

可以询问：

- 下一站有什么？
- 皮箱里还有什么？
- 以后还能不能遇见她？

根据第二幕调查进度和第三幕隐藏物品触发额外剧情。

部分玩家可以获得旧照片收藏品。

## 6.11 场景S29：旅行手账

手账台展示第一日完整记录。

建议包含三页。

### 第一页：登车纪念

展示第一幕信息：

# 七、人物与剧情反馈

## 7.1 人物行为

第一幕主要由乘务鹅引导。

第二幕主要由神秘情报贩子推动。

第三幕重新由乘务鹅承担首日记录、美食和探索引导，情报贩子转为支线角色。

列车长主要承担开场介绍和广播。

严格使用提供的角色形象。

角色动作优先通过独立图层、轻微位置变化、眨眼或表情切换实现。

不得为了动画而随意重画角色五官、服装和比例。

## 7.2 对话必须具有状态记忆

示例：

玩家在第一幕检查过神秘行李，第二幕与情报贩子见面时应增加专属台词。

玩家在第二幕优先调查原始视频，情报贩子可以评价其调查顺序。

玩家完成第二幕全部隐藏调查，第三幕再次见到情报贩子时，可以获得额外留言。

玩家第一幕选择靠窗座位，第三幕访问个人座位时应看到对应场景。

玩家选择特定美食后，手账中应展示相同成品。

这些必须通过实际游戏状态实现。

不允许通过预先写死一套统一对话假装玩家选择产生了影响。

# 八、视觉规范与美术资产使用

## 8.1 总体美术方向

保持统一的：

**复古奇幻列车 × 精致Q版立体鹅 × 2.5D互动场景。**

主要色彩：

- 午夜蓝：#17283D。
- 车厢蓝：#31465E。
- 黄铜金：#C8A875。
- 羊皮纸：#EFE1CA。
- 复古红棕：#83574B。

以深蓝色、胡桃木和暖色灯光建立整体氛围。

不使用普通AI聊天应用式的卡片堆叠布局。

避免过度圆角、大量无意义渐变和廉价发光特效。

文字主要采用清晰的简体中文无衬线字体。标题、票据和少量装饰信息可以使用适当的复古字体风格。

## 8.2 美术素材的调用规则

1. 先检查压缩包中的真实图片和尺寸。
2. 为图片建立清晰的资源映射。
3. 使用手机端和桌面端各自对应的背景资源。
4. 独立道具尽量使用透明PNG或SVG。
5. 所有玩家信息、题目和动态文本由代码渲染。
6. 不将写死在背景里的示例文字作为真实游戏数据。
7. 不用低分辨率预览图替代正式图片。
8. 不拉伸改变鹅角色的比例。
9. 不重复加载相同的大尺寸图片。
10. 对关键素材缺失提供可用的降级方案。

需要特别检查已有素材中部分3D完整效果图和2D矢量组件的材质差异。

不强制把不匹配的素材叠在一起。

可以通过统一的边框、阴影、材质和配色进行适当协调。

## 8.3 场景分层

不能把完整美术图当作所有交互的唯一实现手段。

建议把场景拆分为：

- 背景层。
- 环境动态层。
- 可交互物品层。
- 人物立绘层。
- 对话与UI层。
- 特效与任务提示层。

交互热区需要与可见物品对应。

对于无法直接从背景中拆分出的装饰物，可以使用透明点击热区，但必须能够准确映射到该物件。

建议用相对坐标记录不同端的热区位置。

避免使用只能适配单一分辨率的固定像素坐标。

# 九、手机端与桌面端适配

## 9.1 适配目标

桌面端参考1440×900。

手机端参考390×844。

同时适配不同屏幕尺寸和纵横比。

游戏以移动端可玩为硬性要求。

## 9.2 桌面端

建议采用完整横向场景。

角色、道具、地图与交互区根据场景自由布局。

第二幕调查界面可以采用：

左侧档案列表、中间主操作区、右侧调查笔记。

第三幕展示更宽的列车探索空间。

支持鼠标点击、拖拽、键盘操作和必要的快捷键。

## 9.3 手机端

使用专门的竖屏版式。

场景内容较宽时，允许左右移动视角。

核心交互物品必须始终可见或可通过明确操作找到。

对话从底部弹出。

阅读报纸、调频、制作美食、关联证据时，可以进入专注的全屏交互界面。

所有必要操作必须支持点击完成。

不能要求玩家精准拖动极小的物体。

按钮和热点应具备足够的触控面积。

## 9.4 交互一致性

同一游戏数据只能有一份。

移动端和桌面端共享：

- 剧情选择。
- 道具。
- 投票。
- 任务。
- 食谱。
- 成就。
- 手账。

切换屏幕大小时，不应重置游戏状态。

本地存储只保证同一浏览器环境内的数据持久性，不需要假装实现了跨设备同步。

# 十三、代码结构建议

建议按功能组织，而不是把30个场景写进一个巨大组件。

可以采用以下目录思路：

- `src/game/`：剧情状态、条件判断、任务与存档。
- `src/scenes/`：三幕场景组件。
- `src/components/dialogue/`：对话引擎。
- `src/components/inventory/`：背包和道具。
- `src/components/interaction/`：热点、拖动、谜题。
- `src/components/map/`：七日路线和车厢地图。
- `src/components/journal/`：手账。
- `src/components/sharing/`：分享卡片。
- `src/data/`：剧情、事件、角色、任务和食谱配置。
- `src/assets/`：规范化后的美术资源。
- `src/styles/`：视觉变量、布局和动效。
- `src/utils/`：存储、图片导出、音频等工具。

具体结构以项目实际框架为准。

所有重要功能需要有清晰的组件边界。

游戏逻辑尽量通过状态和数据驱动，不采用大量无法维护的页面跳转硬编码。

# 十四、开发顺序

请按以下顺序推进。

## 第一阶段：资源与技术基础

1. 检查代码仓库。
2. 解压和核查美术资源。
3. 整理角色和场景素材。
4. 建立资源映射。
5. 配置全局主题。
6. 实现游戏状态管理。
7. 实现自动存档。
8. 实现统一的对话、背包、地图和提示系统。
9. 建立移动端与桌面端基础布局。

## 第二阶段：完成三幕核心闭环

优先让玩家能够：

收到邀请函 → 进入车站 → 领取车票 → 检票登车 → 阅读专报 → 初次投票 → 打开皮箱 → 查看证据 → 重新投票 → 自由探索 → 制作美食 → 修复广播 → 完成手账 → 结束第一日。

这一阶段所有关键功能必须能够实际操作。

不要只制作页面外观。

## 第三阶段：补充丰富玩法

进一步完成：

- 分支对话。
- 隐藏道具。
- 环境谜题。
- 支线任务。
- 成就系统。
- 角色记忆。
- 额外食谱。
- 收藏反馈。

## 第四阶段：视觉与动画打磨

完成：

- 正式美术素材替换。
- 双端布局调整。
- 场景动效。
- 音效。
- 角色动作。
- 交互反馈。
- 分享卡视觉优化。

## 第五阶段：完整测试

执行桌面端和移动端测试。

检查：

- 首次游玩是否能通关。
- 所有按钮是否有效。
- 所有必要谜题是否可完成。
- 是否存在卡死状态。
- 能否随时返回。
- 能否保存和恢复进度。
- NPC对话是否符合状态。
- 背包物品能否正确使用。
- 两次投票是否独立保存。
- 个人座位是否正确读取。
- 美食配料是否改变成品。
- 手账是否自动更新。
- 分享图片是否包含正确数据。
- 横竖屏是否存在溢出、遮挡和拉伸。
- 所有本地资源是否加载成功。
- 是否存在控制台错误。

在条件允许时使用自动化浏览器测试完成主线和关键分支验证。

# 十六、最终开发要求

请直接在项目中完成开发，产出一个可以启动并完整游玩的网页游戏。

不要把结果停留在静态设计稿、组件预览页或只有按钮外观的Demo。

需要重点保证以下事项：

**第一，三幕完整打通。**

玩家必须能够从收到邀请函开始，一直玩到第一日结束，且不同章节之间的数据保持连续。

**第二，充分利用现有素材。**

已经生成的背景、角色、道具和UI组件应当被合理利用。优先完成美术资源检查和实际资源映射。

**第三，重视细节。**

每个可交互物品都应有反馈，人物会记得玩家做过的事，场景会根据进度发生变化，隐藏探索应当获得有价值的奖励。

**第四，保证真正的可玩性。**

文字冒险有分支，情报调查有实际操作，自由探索有可发现的秘密，美食有实际制作过程，广播有可完成的机关。

**第五，双端适配是硬性要求。**

不能仅完成桌面版再进行整体缩放。

**第六，先完成再打磨。**

优先保证完整可玩的主线，再补充动画、支线、隐藏彩蛋和视觉细节。

**第七，不编造多人功能。**

当前没有真实后端时，不展示伪造的实时投票比例、用户人数或全局座位占用。使用本地存档实现个人体验。

**第八，保持后续可维护。**

剧情、事件证据、角色台词、站点、食谱与收藏物应采用配置化结构，方便后续更改。

开发过程中发现现有设计存在影响体验或实现的问题，可以在不改变三幕主线和核心玩法的前提下进行合理优化。

最终请提供：

1. 可以运行的完整项目。
2. 所有必要的依赖和启动说明。
3. 清晰的代码结构。
4. 美术资源使用清单。
5. 已实现功能及测试结果。
6. 尚未实现或需要后端支持的功能说明。
7. 可直接体验的完整周一游戏流程。

**最终目标：一款有完整世界观、精致画面、真实交互、剧情反馈和探索价值的《鹅铁U彩》网页冒险游戏，可以用于腾讯鹅创营周一的正式群内互动，并作为后续六天活动的基础平台。**
