# 鹅铁U彩：UI 优化与合并说明

## 交付范围

本版基于用户提供的《鹅铁U彩》代码与素材交接包制作，使用独立副本。交接包 ZIP 的 SHA-256：

`E1C4B25156DC7F8D291845E8D81359FDED0C6D8EC895556A8C1CE4463E2AE261`

保留《鹅铁U彩》作为现有剧情标题，在车票上使用「鹅铁U彩」作为列车名称。此版没有修改场景图片、热点坐标、`SceneStage` 场景绘制或 3D / 2.5D 效果，也没有改变存档数据结构和剧情推进条件。票面日期是实际**出票日期**，条纹只用于装饰，不是可扫描的真实车票码。

## 文件清单

| 文件 | 用途 |
| --- | --- |
| `src/ui-refresh/vintage-ui.css` | 独立的车票、面板、按钮、提示及手机端样式；支持减少动态效果。 |
| `src/ui-refresh/TrainTicket.tsx` | 车票正反面展示组件，仅接收现有车票数据，不直接修改存档。 |
| `src/ui-refresh/ticketDetails.ts` | 出票日期格式化与兼容没有 `crypto.randomUUID` 的浏览器的车票编号。 |
| `src/ui-refresh/ticketShare.ts` | 将同一份真实车票数据生成 PNG；保留隐藏昵称选项。 |
| `src/main.tsx` | 在原有样式之后引入新增 CSS。 |
| `src/scenes/Boarding.tsx` | 将车票显示接入新组件；完善座位选择状态、点击/拖放检票与成功反馈。 |
| `src/utils/share.ts` | 将车票分享图交给独立渲染器，其他分享卡继续使用原有逻辑。 |
| `tests/ui-refresh.test.ts` | 覆盖票号兼容处理和无效日期。 |
| `docs/UI-merge-guide.md` | 本说明。 |

`dist/` 为构建产物，`node_modules/` 为依赖，均不需要作为源代码合并；合并后重新构建即可。

## 与 DeepSeek 版本合并

1. 先在 DeepSeek 版本中保存或提交当前工作，并确认两个版本确实来自同一交接包。不要把本副本整目录覆盖到对方版本。
2. 在 DeepSeek 版本的项目根目录尝试 `git apply --check "补丁文件的完整路径"`。检查通过后再执行 `git apply "补丁文件的完整路径"`。补丁在没有 Git 仓库的目录中也可以用 `git apply` 应用。
3. 如果检查失败，保留对方修改，手动复制合并包中的 `src/ui-refresh/`、`tests/ui-refresh.test.ts` 和本说明，再对照补丁逐处合并 `src/main.tsx`、`src/scenes/Boarding.tsx`、`src/utils/share.ts`。尤其保留对方在同一文件中新增的引用、事件和 3D 初始化，不要直接替换整个文件。
4. 核对 `main.tsx` 中 `vintage-ui.css` 的引入顺序。它应在原有样式之后；若对方的样式也需要覆盖相同 UI 组件，按实际优先级调整并检查。新增样式没有为 `.scene-art`、`.art-board` 或热点设置变换，但如果对方给弹层或票面也添加动画，需检查这些规则是否冲突。
5. 在合并后的项目目录执行 `npm ci`、`npm test`、`npm run build`，再启动网页走查。ZIP 里的补丁在原始交接基底上验证过；对方尚未提供最终版本，因此不能预先保证与该版本无冲突。

## 建议验收

- 从开场依次拆信、填写昵称、选择座位和票面、领取车票、翻看正反面、保存车票、检票、走到站台并登车；刷新后确认进度保留。
- 检查鼠标拖票与手机点击检票；先取消车票选择再检票，确认提示明确，重新选择并成功检票后没有残留错误提示。
- 检查三种票面、最长昵称、隐藏昵称、其他分享卡，以及系统和游戏内的减少动态设置。
- 在微信内置浏览器的真实 iOS / Android 手机上检查排版、触摸、音频和图片保存；合并后再检查 3D 场景、热点点击与切换。模拟浏览器不能替代这一步。
