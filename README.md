# 鹅铁U彩

【值周七组】烧鹅濑粉组呈现。以连续剧情、轻松尝试与自由探索为主的三幕互动网页。使用已有正式鹅设与场景素材，支持手机与桌面，并保留个人车票、调查记录、收藏和手账。

在线地址：<https://vmel6943-commits.github.io/etie-ucai/>

## 启动

需要 Node.js 22.6+ 和 npm。所有美术与MP3配乐均随项目提供，运行时不依赖外部素材网站。

```bash
npm ci
npm run dev
```

生产构建与核心测试

```bash
npm test
npm run build
```

生产文件位于 `dist/`，可部署到静态站点。使用 HashRouter，图片和音乐使用相对路径，支持 GitHub Pages 仓库子目录。

本地检查生产版可运行 `npm run preview`。直接双击 `index.html` 无法运行 React 源码。

## GitHub Pages 发布

项目包含 `.github/workflows/deploy-pages.yml`。将本目录作为仓库根目录推送到 `main`，在仓库 Settings → Pages 中将 Source 设为 GitHub Actions，然后运行发布工作流。后续推送自动重新构建并发布，Actions 的部署记录提供实际访问地址。

工作流会先执行 `npm ci`、`npm test` 和 `npm run build`，再发布 `dist/`。

[GitHub 官方发布说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-for-github-pages)

## 三幕体验

### 第一幕：午夜发车前

拆信 → 到站 → 大厅遇见乘务员 → 填写昵称领取车票 → 检票登车 → 展开旅途地图 → 认识带皮箱的神秘情报贩子。

每个场景都有“下一步”卡片和场景内的主热点两个入口，不设猜编号、机关或必须找齐道具才能推进的条件。怀表、报纸、长椅、行李、服务铃仍然可以探索。

### 第二幕：皮箱里的热点情报

分两段，先读专报，再做五项任务。

1. **列车专报**：三份情报（可口可乐 / 名创优品 / AI 与数学）各自独立保存阅读进度与判断。读完三层传播后必须先留下初次判断，才会出现“揭开真相”。只有可口可乐那份揭开真相后，情报贩子的皮箱才会打开；另外两份只记录、不参与推进。
2. **五项情报任务**（工作台底部五个入口，顺序随意）：
   - 个人观点：两页连续投票，两题都提交才算完成
   - 广告档案：看完后点“记入情报任务”，打开播放室本身不算完成
   - 情报拼图室：四张线索归档全对并提交
   - 舆情急救室：三次公关行动，处理报告出现后点“完成任务”
   - 查看最新信息：四份新闻逐个标记已查阅
3. **最终判断**：五项全完成后记一次“调查后的判断”（只有可口可乐这份有第二判断），随后情报贩子收尾、乘务员在夜行车厢迎接。

五项任务和多步操作都保存中间进度：关掉弹窗再回来会接着上次的位置（拼图、舆情、神秘电波都是如此）。

### 第三幕：夜行列车奇遇记

五个车厢区域自由往返：乘客车厢、观景走廊、列车餐车、广播角、手账台。

美食制作、广播调频、首日见闻、纪念柜、唱针与留声机、旧车票回应都是可选内容，不阻止首日结尾。手账台盖章会把车票、情报记录与最终判断一起收藏，然后播放告别对白并到达结尾页；结尾之后仍可回到车厢继续探索或回看告别。

## 对白与场景同步

- 对白为轻量的电影字幕式面板，保留小头像与姓名，不额外叠加全身立绘。
- 每段对白与面板都绑定来源场景和会话编号；换场景、画内返回、浏览器前进后退都会清掉旧界面与旧回调。
- 对白上的“跳过这段对白”会执行这段对白原本的后续（例如自动打开邀请函、自动接下一步），不会把剧情停在中途。
- 对话历史与设置面板打开时暂停自动播放，并暂停逐字显示。

## 场景配乐

随包包含6首原创器乐循环，单首约40—57秒：

| 场景 | 曲名 | 氛围 |
| --- | --- | --- |
| 邀请函 | 一封午夜来信 | 钟琴、轻钢琴 |
| 到站、领票、站台 | 最后一声汽笛 | 三拍启程曲 |
| 情报与调查 | 皮箱里的回声 | 轻拨弦、钟琴 |
| 车厢、观景走廊、广播角 | 月光越过车窗 | 舒缓夜行曲 |
| 餐车 | 餐车的甜点华尔兹 | 轻快钢琴 |
| 首日结尾 | 把今夜好好收藏 | 温柔收束 |

首次主动开始旅程后播放；场景变化时约1.8秒淡入淡出，对话时降低音乐，离开页面暂停。顶部可静音或恢复，设置中可调音量，选择会保留。所有配乐为本项目原创程序作曲与合成，未使用外部采样。曲目数据与来源见 `public/music/credits.json`。

## 数据与扩展

- 同一浏览器 localStorage 自动存档，支持 JSON 导入/导出。存档结构与版本号未变，旧存档可以直接继续；上一版第二幕的调查记录不算进新的五项任务，进入工作台时会看到提示。
- 三份专报的阅读进度与判断分别保存在 `choices` 的 `report-stage:<id>` / `report-vote:<id>:<first|final>`，不影响存档版本。
- Canvas 导出专属车票、观点卡、美食卡与首日纪念卡；支持隐藏昵称/观点、复制链接与文案，浏览器支持时可系统分享。
- 周二至周日保留锁定预告，等待实际活动安排。
- 当前没有账户、跨设备同步、多人统计或真实抢座。
- 配乐生成脚本需要 NumPy、SciPy 与 ffmpeg，美术重建脚本需要 Pillow；日常运行与部署直接使用已提供的资源，无需执行这些脚本。

验证记录见 `docs/测试报告.md`，修复与验收明细见交接包根目录的 `修改记录.md`。
